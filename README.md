# fund-research-agent

基金产品识别、底层基金归并、官方资料/月报搜索、可追溯用户评论数据管线和痛点/卖点分析工具。

## 功能

1. 读取图片、Excel、CSV、PDF、TXT/Markdown 附件，抽取基金产品代码、晨星代码、ISIN、中英文基金名称。
2. 归并同一底层基金的不同份额；优先使用晨星代码等稳定标识，再使用规范化名称和同管理人范围内的模糊回退，并记录归并方法与置信度。
3. 深度搜索每只底层基金的最新 factsheet、月报、KFS、产品资料概要等资料，抓取正文摘录、识别资料日期、按官方来源/资料类型/新鲜度打分，标记最新候选资料。
4. 补充基金产品主数据，结构化 KID/factsheet/月报字段，覆盖官方费率、风险等级、底层持仓、回撤、流动性、配置和收益风险字段。
5. 识别结构化产品的优先、夹层/平层、劣后分层，分析现金流瀑布、安全垫、预警线、止损线、底层资产流动性和假劣后风险。
6. 使用版本化确定性规则按 `L1/L2/L3` 分类，输出正证据、负证据、覆盖规则、分数向量、置信度路由与人工复核队列；常规路径不消耗 LLM Token。
7. 构建可复现的策略指纹，按资产/收益机制、地区、风格、信用久期、敞口和衍生品用途计算同类相似度，区分 Core / Near / Extended Peer，并阻断不兼容策略。
8. 使用 `fund-market-data-loader-free v1.0.0` 加载免费历史净值，验证真实/不存在代码，保存 SHA256、来源 URL、缓存状态和数据覆盖率；派息份额使用累计净值作为总回报代理。
9. 使用 `fund-peer-score v1.0.0` 计算收益、风险、风险调整收益、持续性、差异化和人民币份额体验，严格区分正式、临时和受阻评分，常规计算为 0 LLM Token。
10. 搜索小红书、微博、抖音近半年针对每家基金公司的公开结果，或读取用户导出的评论 CSV，并将评论标准化为 `FundCompanyMention`。
11. 对评论做脱敏、稳定哈希、去重、近半年自然月窗口标记、风险标记和人工复核队列，按基金公司分析投资者痛点和内容卖点。
12. 配置“基金分析大师”能力层，穿透产品机制、映射投资者痛点、生成下月卖点雷达和反证审计。
13. 输出带来源审计、评分门槛和人工复核队列的 Excel 研究报告。

> 说明：小红书、微博、抖音的评论区通常需要登录且有反爬限制。本项目不绕过登录、验证码、付费墙或平台访问限制；推荐使用平台授权接口、合规第三方数据服务，或用户自行导出的评论 CSV。原始评论、`.env`、业务输入和输出报告不应提交到公开仓库。

## 安装

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
```

图片 OCR 依赖较重；如只读取 Excel/CSV，可以先不安装 `paddleocr` / `paddlepaddle`。

## 配置

复制环境变量模板：

```bash
cp .env.example .env
```

填写搜索和大模型相关 API Key：

```bash
SERPAPI_KEY=your_key
TAVILY_API_KEY=your_key
OPENAI_API_KEY=your_key
```

没有搜索 API Key 也可以运行本地附件读取、基金识别、底层归并、统计和用户导出评论分析。设置 `FETCH_DOCUMENT_TEXT=0` 可只保留搜索结果，不抓取资料正文。

`MAX_DOC_RESULTS_PER_FUND` 控制每只基金保留的搜索结果数，`MAX_DOC_FETCH_PER_FUND` 默认只抓取身份匹配度最高的 3 份正文。搜索结果会完整进入证据表，但仅有 `analysis_eligible=true` 的成功抓取官方/可信资料会进入主数据、分类和评分；同管理人但产品身份不一致的页面会被拒绝。

近半年窗口按自然月计算，默认 `SOCIAL_RECENT_MONTHS=6`。例如运行日为 `2026-06-06` 时，社媒窗口为 `2025-12-06` 至 `2026-06-06`，报告审计表会记录窗口和时区 `Asia/Shanghai`。

## 使用

读取 Excel：

```bash
python main.py data/fund_list.xlsx
```

读取多张图片：

```bash
python main.py image1.jpeg image2.jpeg image3.jpeg image4.jpeg
```

只做本地识别和归并，不做联网搜索：

```bash
python main.py data/fund_list.xlsx --no-doc-search --no-social-search --no-market-data
```

以指定截止日加载免费行情并生成基金对比报告：

```bash
python main.py data/fund_list.xlsx \
  --no-social-search \
  --as-of-date 2026-08-19 \
  --risk-free-rate 0 \
  --output-name fund_research_report_compared.xlsx
```

行情原始响应默认缓存到 `.cache/fund_market_data/`。重复运行会复用缓存；报告会记录来源 URL、抓取时间、内容 SHA256、有效历史长度和接口验证结果。

接入已导出的社媒评论 CSV：

```bash
python main.py data/fund_list.xlsx --social-comments-csv data/social_comments.csv
```

读取 PDF/TXT 附件：

```bash
python main.py attachment.pdf notes.txt --no-social-search
```

运行测试：

```bash
python -m unittest discover -s tests -v
```

输出文件默认在：

```text
output/fund_research_report.xlsx
```

## 社媒评论 CSV 格式

```csv
fund_company,platform,source_type,user_text,publish_time,like_count,url,title
摩根资产管理,小红书,social,这个基金分红挺高但净值也跌了，不知道是不是亏本金,2026-03-12,23,https://...,摩根基金讨论
汇丰资产管理,微博,social,亚洲债券最近是不是受降息预期影响比较大,2026-04-03,8,https://...,汇丰基金评论
```

必要列为 `platform`、`user_text`，以及 `fund_company` / `company` / `product_code` 至少一列。推荐提供：

| 字段 | 说明 |
|---|---|
| `fund_company` | 基金公司中文名，例如 `摩根资产管理`、`惠理集团` |
| `platform` | 小红书、微博、抖音、天天基金、支付宝基金、知乎、雪球等 |
| `source_type` | `social`、`video_comment`、`forum`、`qna`、`complaint_portal`、`app_store`、`news_comment` 等 |
| `user_text` | 用户评论正文或公开摘要 |
| `publish_time` | 发布时间，用于自然月近半年窗口判断 |
| `url` / `link` | 原文链接，用于证据链和哈希去重 |
| `like_count` | 可选互动数据 |
| `title` | 可选页面标题 |

系统会将公开搜索结果标记为 `search_result`，这类记录默认进入人工复核队列，因为搜索摘要不一定等同于真实用户评论。没有日期的记录会保留并标记 `low_confidence_date` 和 `manual_review`。

## 评论数据链路

```text
搜索/导出 -> 标准化 FundCompanyMention -> PII 脱敏 -> 稳定哈希 id_hash
-> duplicate_of 去重 -> 情感/方面/意图标签 -> 风险标记 -> 审计摘要/人工复核 -> 基金公司痛点卖点
```

痛点标签覆盖：亏损/回撤、分红误解、净值波动、汇率/人民币对冲、高收益债信用风险、港股/亚洲市场波动、赎回/申购/费率、平台客服/信息披露。

卖点标签覆盖：高派息/现金流、稳健配置、降息受益、亚洲增长、低估值修复、多资产分散、人民币对冲、品牌信任。

## 基金分析大师能力

项目内置 `fund-mechanism-analyzer`、`fund-peer-performance-underwriter`、`fund-peer-comparator`、`fund-market-narrative-radar`、`fund-investor-pain-mapper`、`fund-evidence-auditor`、`fund-cost-fee-analyzer`、`fund-report-strategist` 八类能力配置。

核心判断链为：

```text
产品清单 -> 底层基金归并 -> 官方资料/月报穿透 -> 产品机制识别
-> 历史业绩/费用/同类证据缺口标记 -> 投资者痛点映射
-> 下月卖点雷达 -> 反证审计 -> 合规传播建议
```

当前版本会先基于已有官方资料、基金类别和用户评论输出机制穿透、痛点映射、下月卖点候选和反证审计；历史净值、费用、完整持仓、外部同类基金池、派息历史和实时市场指标若未接入，会在报告中明确标记为缺失证据，避免把营销词当成投研事实。

## 同类基金定量评分

评分采用底层基金和份额两层、投资质量与差异化双轴设计：

- `InvestmentQualityScore`：收益 30%、风险 30%、风险调整收益 25%、持续性 15%。
- `DifferentiationScore`：结构稀缺性 60%、官方策略证据 25%、历史行为差异 15%，再乘以证据完整度。
- `ShareExperienceScore`：人民币份额总回报 50%、风险 30%、持续性 20%；份额费率和流动性缺失时只能发布临时评分。
- 正式评分要求至少 36 个月、有效基准和至少 5 只 Core 同类；12 个月及至少 3 只 Core 同类可发布临时评分；不满足时分数留空并输出 `blocked_reason`。
- 宽口径资产类别诊断分只用于雷达观察，不替代 Core 同类排名。差异化高表示“不同”，不表示“更好”。

底层基金当前优先选择拥有三年历史的累积份额作为人民币代理序列。报告会明确标注该代理仍可能包含汇率、对冲成本和份额费率影响；未接入策略原币官方序列时，不会把代理结果描述成纯粹的基金经理能力。

## 基金产品主数据

`基金产品主数据` 会按底层基金归并官方资料和份额信息，并从 KID / factsheet / monthly report 的正文摘要中抽取以下字段：

- 官方资料链接：最新 factsheet、KID / 产品资料概要、月报标题、链接和日期。
- 产品属性：投资目标、资产类别、基金分类、基础货币、份额特征、派息政策、人民币/币种对冲、基准。
- 分类关键事实：主要投资策略、收益机制、硬性投资比例、目标敞口区间、衍生品类型与用途、卖空政策、杠杆角色、总/净敞口和市场敞口。
- 官方费率：管理费、经常性开支/ongoing charges、申购费、赎回费、转换费、费率摘要。
- 风险等级：SRI / SRRI / 官方风险等级、风险来源和风险摘要。
- 底层持仓和配置：前十大持仓、资产配置、行业配置、地区配置。
- 债券和收益字段：久期、平均信用评级、到期收益率、派息率。
- 回撤和流动性：最大回撤、交易频率、结算周期、赎回流动性。
- 数据质量：主数据完整度分数、缺失字段、证据链接。

无法从官方资料中结构化识别的字段不会被猜测，会进入 `missing_master_fields`，供后续人工复核或接入净值/费率/持仓数据源补齐。

## 确定性分类和同类基金引擎

分类链路为：

```text
份额身份 -> 底层基金 -> 最新官方披露 -> 分类事实包
-> 确定性评分/负证据/覆盖规则 -> 置信度路由
-> 策略指纹 -> 硬兼容性检查 -> Core / Near / Extended Peer
```

证据优先级遵循“明确收益机制 > 主要投资策略 > 硬性投资政策 > 目标区间 > 实际持仓 > 基准 > 基金名称”。名称仅作为低权重线索；缺失字段保持未知，不会自动当作否定证据。

关键反误判规则：

- 仅使用期货、期权或掉期，不足以判定 CTA；必须有系统化趋势、核心衍生品和收益生成用途等机制证据。
- `long/short` 不等于市场中性；缺少低 Beta、低净敞口或明确中性机制时，不进入 Market Neutral。
- 多资产配置不等于另类 Multi-Strategy；必须披露多个另类收益机制。
- 人民币对冲是份额属性，不增加底层基金的市场中性分数。
- 任一基金的分类未达到自动接受门槛时，Core/Near 同类关系会自动降一级并标记 `provisional_downgrade`，避免名称线索直接形成强同类结论。

版本字段当前为 `fund_taxonomy_v1`、`classifier_rules_v1`、`classification_v1`、`policy_fp_v1` 和 `peer_weights_v1`。置信度在完成 gold set 校准前仅是复核路由分数，不表示统计意义上的正确概率。

## 结构化产品分层分析

系统会从 KID / factsheet / 合同摘要 / 月报正文中保守识别结构化产品条款。未出现明确分层语言时，不会强行判断为结构化产品。

结构化分析覆盖：

- 分层结构：优先、夹层/平层、劣后。
- 收益分配顺序：优先 > 夹层/平层 > 劣后。
- 亏损吸收顺序：劣后 > 夹层/平层 > 优先。
- 安全垫：劣后安全垫比例、优先级条款披露情况。
- 风控线：预警线、止损线、止损可执行性。
- 底层资产流动性：标准化资产/每日交易为较高流动性线索，非标、未上市股权、不动产等为低流动性风险线索。
- 风险标记：`missing_tranche_terms`、`missing_junior_cushion`、`missing_warning_line`、`missing_stop_loss_line`、`low_liquidity_stop_loss`、`fake_subordination`。

分析结论会区分“优先级是否有真实安全垫”和“劣后是否只是跟投或心理安慰”。优先级卖点必须同时具备底层现金流、劣后安全垫和止损可执行性证据。

| 份额人民币体验 | 累积/派息、对冲/非对冲份额的人民币体验和同底层排名 |
| 同类池定义 / 评分受阻原因 | Core/Near/Extended 口径、正式/临时/受阻门槛和补数动作 |
| 评分方法说明 / 行情采集审计 | 版本、权重、假设、接口验证和 0 Token 审计 |

## 实现边界

- 官方资料搜索使用 SerpAPI 和 Tavily；同时配置时会合并去重。系统会优先识别官方/基金经理域名，但最终资料有效性仍应由研究员复核。
- 最新资料通过标题、链接、摘要和抓取正文中的日期识别，并结合资料类型和来源质量评分；无法识别日期的资料不会被强行当作最新。
- 确定性分类正常路径为 0 LLM Token；低置信结果先补官方证据，当前版本不会用大模型覆盖明确投资政策。
- 社媒搜索只使用公开网页结果和用户提供的导出评论，不绕过平台登录、验证码或反爬机制。搜索和分析维度为基金公司；若需要真实评论区全量样本，应接入平台授权接口或合规第三方数据服务。
- 评论分析不做个人画像；系统会脱敏手机号、邮箱和长数字标识，并把低置信样本输出到人工复核队列。
